# 12. 演示、答辩与术语

## 1. 90 秒演示脚本

### 0–15 秒：目标

“Nucleus 是一个给非技术用户使用的 AI 网页应用生成器。输入一句需求，它会规划、生成、检查并交付一个真实可运行的前端应用。”

### 15–45 秒：核心链路

输入一个具体需求，例如：

```text
做一个个人旅行预算面板，可以新增支出、按类别统计，并显示剩余预算。
```

指出左侧 Iris/Bob/Alex/Ray 的实时状态、产品计划和三个文件写入事件。不要只等进度条，解释这是服务端 NDJSON 事件流。

### 45–65 秒：证明可用

在预览中新增一条支出，观察统计更新；切到代码页展示 HTML/CSS/JS；切手机宽度展示响应式。

### 65–80 秒：证明可迭代

展示已经准备好的 v2（避免现场第二次等待），恢复 v1 再恢复 v2，说明每次生成保存全量 D1 快照。

### 80–90 秒：交付

点击发布，打开 `/p/[slug]`；说明还可下载 ZIP，源码和在线链接均公开。

## 2. 演示前准备

- 提前打开首页、一个已有 v2 的工作台、公开页和 GitHub；
- 确认网络、模型额度和在线 API；
- 准备一个简短需求，避免生成超大页面；
- 关闭可能泄露通知、Key 或个人信息的窗口；
- 浏览器缩放 100%；
- 准备失败兜底：已有版本、录屏、进度记录；
- 不要在现场展示 `.env.local`。

## 3. 面试官常问：这是不是套壳？

回答要点：

“模型负责生成不确定内容，但产品工程不是一次 API 转发。我定义了两阶段协议、path code fence 解析、漏文件定向修复、增量合并、文件白名单和大小校验；再用 D1 做版本快照、NDJSON 做进度、sandbox iframe 做运行隔离，并处理了线上限流、发布和错误回传。”

## 4. 为什么不用完整 Next/Vercel

“目标托管环境是 Worker + D1，所以使用 Vinext 和 Cloudflare Vite 插件把 App Router 项目构建为 Worker 产物。这样前端、API 和数据库 binding 一次部署。技术选择服从部署和数据需求，不是只看框架热度。”

## 5. 为什么不用 WebSocket

“当前通信是服务端单向推送阶段事件，不需要浏览器在同一连接上持续回传。NDJSON 基于普通 fetch，可读流实现简单、代理兼容性好。需要取消、协同编辑或双向 agent 控制时，再评估 WebSocket/SSE。”

## 6. 为什么不是 SSE

“SSE 也能做单向流。这里每个事件本身就是 JSON，NDJSON 在 POST fetch 响应中解析直接，不需要 `data:` framing。代价是要自己处理分块 buffer 和重连；当前一次生成请求不做自动重连。”

## 7. 为什么版本用全量快照

“文件只有三份且体积受限，全量快照让恢复是一次读取和更新，可靠性高。差量存储更省空间，但恢复要依赖整个补丁链。MVP 阶段优先简单正确，规模增长后再做压缩或对象存储。”

## 8. 最大技术难点是什么

推荐回答三个，而不是泛泛说“前端很难”：

1. 模型输出不稳定：大 JSON 损坏、空内容、漏文件和增量文件；
2. 不受信任代码预览：sandbox、storage shim、错误桥和标签边界；
3. 线上闭环：Worker、D1 binding、secret、长请求、版本发布和额度保护。

每个难点都要说“症状—根因—修复—仍有限制”。

## 9. 如果再给一周做什么

优先级建议：

1. 登录和项目所有权，堵住公开项目读写；
2. 后台生成队列、取消和超时；
3. Playwright 自动验收与修复循环；
4. 固定 version 发布与一键回滚；
5. 指标、日志、成本仪表盘；
6. CSP、网络策略和内容审核；
7. 最后才扩大生成技术栈。

## 10. 如何说明开源参考和 AI 协作

如实表述：

“我研究了成熟 AI builder 的产品结构和运行时思路，并检查了上游许可证；最终没有直接复制一个我无法解释的大型仓库，而是围绕笔试的三文件 MVP 独立实现。开发中使用 AI 协助检索、编码、排错和文档，但核心协议、范围、安全边界和上线验收由我确认，代码和第三方说明公开可查。”

不要声称完全手写，也不要把不理解的代码说成自己的原创设计。

## 11. CLI 和 IDE

### CLI

Command Line Interface，命令行界面。例如 PowerShell 中运行：

```powershell
git status
pnpm test
gh pr create
```

优势是可复制、可自动化、适合脚本和服务器；缺点是需要记命令，反馈偏文本。

### IDE

Integrated Development Environment，集成开发环境，例如 VS Code、WebStorm。它把代码编辑、文件树、搜索、调试、Git 和扩展放在图形界面中。

IDE 不是 CLI 的替代品。正常开发常在 IDE 写代码，在内置终端运行 CLI；二者操作的是同一批文件和 Git 仓库。

### Claude Code / Codex 属于什么

它们更接近能读取工程、调用终端和修改文件的 coding agent。可以运行在 CLI 或桌面/IDE 集成中。能力载体不同，但最终仍通过文件、命令、Git diff、测试和 PR 进入工程流程。

## 12. 核心术语表

| 术语 | 白话解释 |
|---|---|
| API | 两个程序约定如何请求和返回数据 |
| Endpoint | 一个具体 API 地址与方法 |
| HTTP 200/400/500 | 成功/请求错误/服务端错误类别 |
| JSON | 常用的结构化文本数据格式 |
| NDJSON | 每一行都是一个独立 JSON 的流格式 |
| Stream | 数据边产生边传输，不必全部结束才收到 |
| React component | 根据输入和状态描述一块 UI 的函数 |
| State | 组件当前记住、变化后会重新渲染的数据 |
| Hook | React 中复用状态、生命周期等能力的函数 |
| Route | URL 到页面或 API 处理器的映射 |
| Worker | 接收请求并在云端运行服务端逻辑的程序 |
| Binding | 平台把 D1 等资源注入 Worker 的命名连接 |
| D1 | Cloudflare 托管的 SQLite 风格数据库 |
| Migration | 可追踪、按顺序执行的数据库结构变化 |
| ORM | 用程序结构描述/操作数据库的工具层 |
| iframe | 页面里独立嵌入的另一个网页文档 |
| sandbox | 对 iframe 可用能力的权限限制 |
| `srcDoc` | 直接把 HTML 字符串作为 iframe 文档 |
| `postMessage` | 不同窗口/iframe 之间发送结构化消息 |
| Runtime | 代码实际运行所依赖的环境和辅助逻辑 |
| Build | 把源代码转换成可部署产物 |
| Deploy | 把某个版本放到运行环境接收流量 |
| Secret | 不可进入源码和客户端的敏感配置 |
| Hash | 将输入转换为固定摘要，通常不可逆还原 |
| Rate limit | 限制一段时间内可调用次数 |
| Repository | 由 Git 管理的一整个项目目录和历史 |
| Branch | 指向一条开发历史的可移动名称 |
| Commit | 一次带作者、时间和说明的变化快照 |
| Remote | 远端 Git 仓库地址 |
| Push/Pull | 上传/下载 Git 提交 |
| PR | 提议审查并合并一组分支变化 |
| CI | 每次提交自动运行测试、检查和构建 |
| CD | 自动把已验证版本交付/部署到环境 |
| Smoke test | 部署后快速验证最关键主路径 |
| Rollback | 把生产流量恢复到已知稳定版本 |
| PoC | 证明想法可行的实验，不一定可交付使用 |
| MVP | 用最小范围完成真实用户闭环的产品 |

## 13. 最后一句总结

这个项目最值得讲的不是“页面像某个产品”，而是：在有限时间里，把不稳定的 AI 输出收敛成可验证文件，安全地运行，可靠地保存和发布，并用真实线上证据证明主链路完成。
