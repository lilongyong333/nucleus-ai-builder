# Nucleus — 笔试提交说明

在线体验：https://nucleus-ai-builder-root.dreamy-joy-4746.chatgpt.site

已发布示例：https://nucleus-ai-builder-root.dreamy-joy-4746.chatgpt.site/p/app-c4fbb7

## 1. 我对题目的理解

题目考查的不只是能否调用大模型，而是能否在有限时间内做出一条真实、稳定、可解释的产品闭环：生成结果能运行，项目能保存，评审人能继续修改并通过公开链接验证。

## 2. 实现思路

产品上采用“AI 团队正在为你工作”的三栏工作台。技术上采用两阶段生成：Iris 先产生结构化产品计划，Alex 再输出带路径的三个代码文件。浏览器将三文件组装进 sandbox iframe，不在服务器执行用户生成代码。

## 3. 关键取舍

- 只生成前端三文件，换取在线演示的可靠性；
- D1 保存项目和全量版本快照，而不是浏览器本地存储；
- path code fence 传输长代码，避免大 JSON 转义失败；
- 游客直接体验，不用登录阻断评审路径；
- 选择实测约 32 秒的 `glm-5.2`，不为了模型数量做高成本 Race Mode。

## 4. 已完成功能

- 真实 AI 应用生成与继续修改；
- 结构化 Agent 计划和执行时间线；
- 可点击实时预览、源码查看和移动视口；
- 运行错误回传与修复入口；
- 项目持久化、版本恢复；
- 公开发布链接、ZIP 下载；
- 响应式界面、错误状态和预置可运行内容。

## 5. 扩展能力

本项目选择“运行时自愈入口 + 版本检查点”作为衍生能力。iframe 将运行错误交给工作台，用户可以一键让 Ray 带着错误信息继续修复；每轮结果同时保存为版本，修复失败也能恢复。

## 6. 局限与继续投入方向

当前不生成后端和任意 npm 依赖。如果继续投入，优先增加 esbuild-wasm React 运行时、模型自动补全、截图视觉复检和用户身份/权限，最后才扩展到隔离容器中的全栈生成。

## 7. 演示建议（60–90 秒）

1. 首页输入“旅行预算规划器”；
2. 展示四个 Agent 的计划和执行过程；
3. 在生成应用里新增、删除一笔预算；
4. 输入“增加深色模式”继续修改；
5. 打开版本历史，恢复上一版再切回；
6. 点击发布，打开无平台 UI 的公开页；
7. 点击下载，展示三文件代码包。

## 8. AI 工具使用

Codex 用于需求拆解、上游审阅、实现、测试与文档；OpenCode Go 用作产品内部的规划和生成模型。项目保留了逐阶段的实际问题与修复记录，见 `docs/PROGRESS.md`。
