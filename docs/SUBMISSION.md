## 1. 我对题目的理解

题目考查的不只是能否调用大模型，而是能否在有限时间内做出一条真实、稳定、可解释的产品闭环：生成结果能运行，项目能保存，评审人能继续修改并通过公开链接验证。

## 2. 实现思路

产品上采用“AI 团队正在为你工作”的三栏工作台。技术上采用可恢复的真实固定 SOP：Iris 形成需求契约，Bob 形成架构，Alex 分阶段生成三个代码文件，Ray 做确定性检查、应用类型专项检查、模型代码审查和有限修复。浏览器将通过质量门的三文件组装进 sandbox iframe，不在服务器执行用户生成代码。

## 3. 关键取舍

- 只生成前端三文件，换取在线演示的可靠性；
- D1 保存项目和全量版本快照，而不是浏览器本地存储；
- path code fence 传输长代码，避免大 JSON 转义失败；
- 游客直接体验；Sign in with ChatGPT 后匿名项目、版本和对话迁移到账号并跨设备保存；
- 当前套餐真实规划/长代码探针后选择 `gpt-5.6-luna` 作为主模型、`glm-5.2` 作为备用；不为凑数量做无工件的高成本 Race Mode；
- 整轮允许 24 次调用/180K Tokens，但每个 Agent 阶段仍控制在边缘执行窗口，并在阶段之间落盘。

## 4. 已完成功能

- 真实 AI 应用生成与继续修改；
- Iris/Bob/Alex/Ray 的独立模型动作、结构化工件和执行时间线；
- 可点击实时预览、源码查看和移动视口；
- 运行错误回传与修复入口；
- 项目持久化、版本恢复；
- 匿名会话数据隔离、同项目并发生成保护和可取消请求；
- 固定版本的公开发布链接、ZIP 下载；
- Ray 质量评分、GitHub Actions 和 Playwright 浏览器回归；
- 每轮生成的可展开执行审计：Agent 阶段、耗时、Token、模型调用数、修复次数与最终状态；
- 账号项目中心、工作台/公开成品详细链接、最近 100 条项目对话记忆；
- 主备模型自动切换、Run/阶段两层调用/Token/时间预算；
- 预览启动校验、长任务心跳、Artifact 检查点、浏览器断流后从当前阶段恢复与遗留任务取消；
- v0 真实空状态、响应式界面和明确错误状态，不用固定旧 Demo 冒充新生成结果。

## 5. 扩展能力

本项目选择“运行时自愈入口 + 版本检查点”作为衍生能力。iframe 将运行错误交给工作台，用户可以一键让 Ray 带着错误信息继续修复；每轮结果同时保存为版本，修复失败也能恢复。

## 6. 局限与继续投入方向

当前不生成后端和任意 npm 依赖。平台账号、项目和对话已持久化，但单个生成应用仍是自包含前端，不拥有独立数据库/Auth。下一优先级是云端浏览器点击/截图 QA 和受控生成应用数据 API，最后才扩展到隔离容器中的任意全栈执行。

## 7. 演示建议（60–90 秒）

1. 用 ChatGPT 登录，展示账号项目中心、工作台详细链接和公开成品链接；
2. 打开面试项目冲刺看板，新增任务并连续流转到完成；
3. 展示总数/完成率实时更新、“启动校验通过”和 Ray 100/A；
4. 展开执行审计，说明 21 秒、6,293 Tokens、1 次模型调用和运行 ID；
5. 打开对话记忆与版本历史；
6. 输入“增加预算超支提醒”继续修改并展示状态恢复/取消；
7. 发布并打开固定版本公开页；
8. 点击下载，展示三文件代码包。
